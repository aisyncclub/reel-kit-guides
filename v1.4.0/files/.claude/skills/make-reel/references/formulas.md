# 공식 고르기 (릴스 키트 2단계)

> 이 파일의 `---` 아래는 hook-engine 의 「골라 쓰는 공식 7가지」 원문 그대로예요(문장은 바꾸지 않았어요). 키트에 맞춰 더한 것은 이 머리말과, 6 · 7번 옆의 「카드뉴스 키트에서」 표시뿐입니다.

## 이 키트에서 쓰는 법

- **언제**: 2단계에서 주제를 정한 뒤, 3단계 대본을 쓰기 전에. 대시보드 2단계의 「공식 고르기」 줄이 이 파일의 표를 그대로 보여 줘요
- **누가 고르나**: 사용자가 대시보드에서 하나 누르거나 「Claude가 골라 줘」를 눌러요. 고른 값은 `episodes/state.json` 의 `formula` 에 남아요(`1`~`5` 또는 `"auto"`). 채팅으로 정하게 하면 아래 「소재만 주면 이렇게 고른다」 순서로 1순위와 2순위를 추천하고 하나만 확인받아요
- **고른 뒤**: 그 공식의 뼈대(「줄 / 역할 / 빈칸 틀」 표)가 이 편 대본 뼈대예요. `references/script.md` 의 훅 꼴 · 점검표 · 분량과 함께 쓰고, 둘이 부딪치면 `script.md` 와 `SKILL.md` 의 절대 규칙이 먼저예요
- **릴스 공식은 1~5**: 6 · 7번은 카드뉴스 키트에서 쓰는 공식이라 이 키트에서는 고르지 않아요. 소재가 6이나 7에 맞으면 "이 소재는 카드뉴스 키트에서 만드는 게 맞아요"라고 알리고, 릴스로 만들 거면 1~5 중에서 골라요
- **끝 멘트 줄**: 이 편의 마지막 화면 꼴(`cta`)을 따라요. `save` 면 FLOW 의 저장 · 팔로우 문장, `keyword` 면 공식의 CTA 틀
- 원문에 나오는 파일 이름(`hooks.md` · `scripts.md` · `funnel-cta.md` · `scripts/score_hook.py` · ow-reels 가이드)은 원래 hook-engine 쪽 파일이에요. 이 키트에는 없으니 찾지 않아요. 훅 후보 · 점검표 · 분량은 `script.md` 가 같은 일을 해요

# 골라 쓰는 공식 7가지

출처: insta_auto_claude/videos/REEL-FORMAT-0905new.md(릴스 9~10줄 뼈대, 훅 A 오귀인 / B 숫자+전수, 1-1 소개형, 1-2 쇼츠판), insta_auto_claude/docs/CARDNEWS.md §0(증거 카드뉴스 9장)·§11(화면 템플릿), insta_auto_claude/docs/CONTENT-RULES.md(훅 배점·배지·캡션), ow-reels-kit/skills/ow-reels(35초 위아래 분할, 댓글 키워드 → DM, 구조만), 이 스킬의 hooks.md·scripts.md·funnel-cta.md·ideas.md. 남의 문장은 옮기지 않았고, 원본에 없는 예문은 [빈칸]으로 뒀다.

소재를 받으면 어떤 틀로 쓸지부터 정한다. 아래 7개 중 하나를 고르면 그 공식의 뼈대가 그대로 6단계 대본(또는 카드 구성)이 된다.

## 공식 고르기 표

| # | 이름 | 형식 | 이럴 때 | 필요한 재료 |
|---|---|---|---|---|
| 1 | 통념 뒤집기 | 릴스 9줄 | 사람들이 이미 겪는 문제인데 원인을 잘못 알고 있을 때 | 진짜 원인 한 줄, 이름 붙일 3단계, 실측 숫자 대비 하나 |
| 2 | 전부 해 봤다 | 릴스 10줄 | 우리가 N개를 실제로 다 해 봤을 때 | 해 본 개수와 기록, 같은 문형으로 말할 5가지, 출처 |
| 3 | 도구 N개 소개 | 릴스 | 도구·스킬 여러 개를 추천할 때 | 도구별 불편 한 줄과 해결·증거 한 줄, 실제로 돌린 결과, 범위 주의 한 줄 |
| 4 | 숫자 + 방법 직설 | 릴스 | AI 정보 숏폼 기본. 방법 N개를 바로 줄 때 | N개 방법, 그중 가장 센 것 하나 |
| 5 | 댓글 키워드 따라 하기 | 릴스 35초, 위아래 분할 | 설치·설정 튜토리얼 | 따라 할 수 있는 3~4단계, 결과 화면, 댓글로 보낼 설치 문서 |
| 6 | 증거 카드뉴스 | 카드 9장 (카드뉴스 키트에서) | 공식 발표·숫자·원문이 있는 소식 | 원문 캡처, 확인한 숫자와 출처, AI 답 발췌(있으면) |
| 7 | 화면 카드뉴스 | 카드 8~9장 (카드뉴스 키트에서) | 프롬프트 모음, 활용 결과물 | 실제로 받은 결과 화면, 넣은 프롬프트, 전후 비교 |

## 소재만 주면 이렇게 고른다

위에서 아래로 보고 처음 맞는 것을 1순위로, 다음으로 맞는 것을 2순위로 낸다(둘을 추천하고 하나 확인받는다).

1. 내가 직접 다 해 본 개수와 기록이 있다 → 2
2. 도구·스킬을 여러 개 추천한다 → 3
3. 설치·설정을 따라 하게 하고 DM으로 문서를 줄 수 있다 → 5
4. 공식 발표·숫자·원문 캡처가 있는 소식이다 → 6
5. 프롬프트 모음이거나 결과 화면이 주인공이다 → 7
6. 사람들이 원인을 잘못 알고 있고, 진짜 원인과 숫자 대비가 있다 → 1
7. 위 어디에도 안 맞고 방법이 N개로 떨어진다 → 4

- 같은 소재가 둘에 걸리면 숫자 근거가 센 쪽이 앞이다. 근거가 약한 공식은 쓰지 않는다(2는 실제로 다 했을 때만, 1은 진짜 원인이 확인됐을 때만).
- 재료 칸이 비면 그 공식은 못 쓴다. 지어서 채우지 않고 다음 공식으로 내려간다.
- 같은 공식을 3편 연속 쓰지 않는다. 훅 유형과 배지도 편마다 바꾼다.

## 1. 통념 뒤집기 (릴스)

| 칸 | 내용 |
|---|---|
| 이럴 때 | 시청자가 이미 겪는 문제가 있고, 흔한 원인 설명이 틀렸다고 실측으로 말할 수 있을 때 |
| 커버 | 배지 1줄(B1 2인칭 지목 우선) + 타이틀 3줄 `[대상] / [의무·최상급] / [명사구 마감]`, 줄당 4~7자. 마지막 줄은 명사구(~습관 3개, ~법) |
| 첫 1초 | 커버 첫 줄과 같은 말. 둘째 문장에서 이유·사건·숫자로 한 겹 더 |
| 끝 멘트 | "…는 자료에 담았어요. 댓글에 [키워드]. [브랜드 끝 카피]" 쇼츠판은 "…는 고정 댓글에 있어요. 도움 됐다면 구독과 좋아요 부탁드려요." |
| 우리 예 | 클로드 한도 습관 3가지. 훅 "내 클로드 한도가 빨리 차는 건, 많이 써서가 아니에요." 결핍 "저도 짧게만 물어봤거든요." 원리 "토큰이니 컨텍스트니 몰라도 됩니다. 치우는 순서만 알면 돼요." 이름 "확인, 정리, 박제." 숫자 대비 "30턴이면 같은 지시를 30번 다시 읽어요. 파일로 옮기면 1번이면 끝나요." |
| 하지 말 것 | 원인을 확인하지 않고 통념을 반박하기 / 용어 설명으로 03을 채우기(용어는 버린다) / 스텝 문형을 섞기 / 센 결과에 범위를 좁히는 문장을 빼기 |

| 줄 | 역할 | 빈칸 틀 |
|---|---|---|
| 01 | 훅(오귀인) | [문제]는 [통념] 때문이 아니에요. |
| 02 | 1인칭 결핍 | 저도 [같은 행동]했거든요. |
| 03 | 원리 한 줄, 용어 버리기 | [어려운 말] 몰라도 됩니다. [핵심 순서]만 알면 돼요. |
| 04 | 개수 선언 + 두 글자 이름 | [행동]은 딱 [N]개면 됩니다. [이름1], [이름2], [이름3]. |
| 05~07 | 스텝, 같은 문형 | 먼저 [이름1]. [한 줄] / 다음은 [이름2]. [한 줄] / 마지막은 [이름3]. [한 줄] |
| 08 | 숫자 대비 | [큰 숫자]번 [나쁜 일]. [방법]하면 [작은 숫자]번이면 끝나요. |
| 09 | CTA | [자료]는 자료에 담았어요. 댓글에 [키워드]. [브랜드 끝 카피] |

## 2. 전부 해 봤다 (릴스)

| 칸 | 내용 |
|---|---|
| 이럴 때 | 우리가 N개(장·번·개)를 실제로 다 해 봤고, 결과를 고르는 기준을 말할 수 있을 때 |
| 커버 | 배지 1줄 + 3줄. 숫자 맨 앞이 자연스럽다 `[도구] / [N개 전부 해 본] / [결과 명사구]` |
| 첫 1초 | 커버 첫 줄과 같은 말. 숫자와 "전부"를 첫 문장에 둔다 |
| 끝 멘트 | 릴스는 위와 같은 CTA 고정 포맷. 출처 줄(09)에서 남이 만든 것이면 누가 만들어 공개했는지 밝히고 우리가 더한 것(쓰는 법, 한글화)을 말한다 |
| 우리 예 | 차트 64장. 훅 "클로드가 그린다는 차트. 64장을 전부 뽑아봤습니다." 결핍 "내 보고서 차트는 늘 막대 아니면 원이었어요. 문제는 감각이 아니었습니다." 원리 "차트는 내가 고르는 게 아니에요. 데이터 모양이 정합니다." 스텝 문형 "순위를 보여줄 자료면 점을 셉니다." "비중이면 원 대신 점 100개를 깝니다." 숫자 대비 "64장 → 5가지" |
| 하지 말 것 | 안 해 본 것을 "전부 해 봤다"고 하기(이 훅은 실제로 다 했을 때만) / 스텝마다 문형이 달라지기 / 04 개수 선언을 따로 두기(5스텝이면 03에 붙인다) |

| 줄 | 역할 | 빈칸 틀 |
|---|---|---|
| 01 | 훅(숫자+전수) | [도구·주제]. [N개]를 전부 [해봤습니다]. |
| 02 | 경험 + 결핍 | [내 상황]은 늘 [불편]이었어요. 문제는 [오해한 원인]이 아니었습니다. |
| 03 | 원리 한 줄(개수 선언 흡수) | [판단 기준]은 내가 고르는 게 아니에요. [기준]이 정합니다. 결국 [M]가지예요. |
| 04~08 | 같은 문형 5개 | [조건]이면 [행동]합니다. (다섯 번 같은 꼴) |
| 09 | 출처 또는 숫자 대비 | 이건 [누가] 만들어 공개한 [것]이에요. 여기에 [우리가 더한 것]을 더했습니다. / [N] → [M] |
| 10 | CTA | [자료]는 자료에 담았어요. 댓글에 [키워드]. [브랜드 끝 카피] |

## 3. 도구 N개 소개 (릴스)

| 칸 | 내용 |
|---|---|
| 이럴 때 | 도구·스킬 여러 개를 소개하고, 하나하나 실제로 돌려 본 결과가 있을 때 |
| 커버 | 배지 1줄 + 3줄 `[대상] / [N개 도구·스킬] / [결과 명사구]`. 대상은 상황으로 시작하면 좋다 |
| 첫 1초 | 대상 + 숫자 + 하는 일을 한 문장으로("[대상], [일] 전에 [도구] [N]개"). 둘째 문장에서 가장 센 쓰임 한 겹 |
| 끝 멘트 | "[N]개 링크와 쓰는 법은 자료에 담았어요. 댓글에 [키워드]. [브랜드 끝 카피]" |
| 우리 예 | 자소서 AI 스킬 4개. 훅 "취준생 자소서, 서류 광탈 전에 AI 스킬 4개. 감점부터 찾아요." 이유 "왜 스킬이냐면요. 첨삭 기준을 매번 프롬프트로 길게 안 써도 돼요." 소개 "1번, jobstack. 자소서 감점을 7가지로 진단하고 점수를 매겨요." 쓰는 법 "스킬을 깔고 공고와 자소서를 같이 넣으면 돼요." 주의 "다만 합격 보장은 아니에요." |
| 하지 말 것 | 결핍·원리·이름 붙이기 뼈대를 끌어오기(소개형은 곧게 간다) / 스킬에 두 글자 별명 붙이기(번호와 원래 이름으로 부른다) / 안 돌려 본 결과를 "이렇게 쓴다"에 넣기 / 불편 줄 없이 이름과 결과만 말하고 넘어가기 / 합격 보장 같은 센 말을 주의 줄 없이 두기 |

| 줄 | 역할 | 빈칸 틀 |
|---|---|---|
| 01 | 훅 | [대상], [상황] 전에 [도구] [N]개. [가장 센 쓰임]부터 해요. |
| 02 | 쓰는 이유(확인한 것만) | 왜 [도구 종류]냐면요. [아끼는 것]을 매번 [번거로움] 안 해도 돼요. |
| 03~ | N번 소개, 같은 문형 | [번호]번, [원래 이름]. [하는 일]. |
| 같은 자리 | 불편 한 줄 | [그 불편이 보이는 상황]이면, [번거로운 일]이 몇 번씩 되죠? |
| 같은 자리 | 해결·증거 한 줄 | 이 스킬은 [해결]해 줘요. [우리가 잰 숫자] |
| 다음 | 이렇게 쓴다 | 쓰는 법은 간단해요. [순서]하면 돼요. (실제로 돌린 결과만, 화면에 실행 조건 라벨) |
| 다음 | 주의 | 다만 [범위를 좁히는 말]이에요. |
| 끝 | CTA | [N]개 링크와 쓰는 법은 자료에 담았어요. 댓글에 [키워드]. [브랜드 끝 카피] |

## 4. 숫자 + 방법 직설 (릴스)

| 칸 | 내용 |
|---|---|
| 이럴 때 | AI 정보 숏폼의 기본형(10/25 지시). 통념 반박보다 숫자와 방법을 곧바로 주는 쪽이 맞을 때 |
| 커버 | 배지 1줄 + 3줄 `[대상] / [숫자]가지 / [~하는 법]`. 숫자는 양념이고 장치는 대상 호명과 명사구 마감 |
| 첫 1초 | 훅 문장이 곧 커버 첫 줄. 인사·소개 없이 바로 1번으로 간다 |
| 끝 멘트 | 마지막 방법(가장 센 것)을 말한 바로 뒤에 CTA 고정 포맷 하나만 |
| 우리 예 | AI 티 10가지 지우는 법 |
| 하지 말 것 | 도입에 설명 평서문 깔기 / 방법을 순서 없이 나열만 하기(원 포인트 원칙에 어긋나면 개수를 줄이고 나머지는 자료로) / 약속한 N을 다 싣느라 한 장면에 둘 이상 넣기 / 약한 것을 마지막에 두기 |

| 줄 | 역할 | 빈칸 틀 |
|---|---|---|
| 01 | 훅 | [대상]이 [피하고 싶은 것] [N]가지 [~하는 법]. |
| 02~(N+1) | 방법 1번부터 바로, 같은 문형 | [번호]번, [방법 이름]. [한 줄 설명]. |
| 마지막 방법 | 가장 센 것을 끝에 | 마지막은 [가장 센 방법]. [왜 이게 제일 센지 실측 한 줄] |
| 끝 | CTA | [나머지·전체]는 자료에 담았어요. 댓글에 [키워드]. [브랜드 끝 카피] |

## 5. 댓글 키워드 따라 하기 (릴스 35초, 위아래 분할)

| 칸 | 내용 |
|---|---|
| 이럴 때 | 설치·설정 튜토리얼이고, 실제 설치 절차를 DM으로 보낼 문서가 이미 있거나 같이 만들 때(문서가 없으면 만들지 않는다) |
| 커버 | 배지 1줄 + 3줄, 또는 결과가 보이는 첫 장면 그대로. 줄당 4~6자로 끊는다 |
| 첫 1초 | 결과 먼저. 만든 결과나 숫자 증거를 화면과 말로 같이 보여 준다(숫자는 출처를 확인한 것만) |
| 끝 멘트 | "설치 문서는 DM으로 보내 드려요. 댓글에 [키워드]." 마지막 화면 글자가 그 키워드와 같은 단어 |
| 우리 예 | 원본 파일에 우리 문장이 없다. 소재가 정해지면 [빈칸]으로 채운다(ow-reels 스킬 산출 순서 ①~⑧을 따른다) |
| 하지 말 것 | 영상에서 설치 절차를 전부 알려 주기(단계 이름만 보여 주고 절차는 문서로) / DM 자료 없이 키워드부터 걸기 / 확인 안 한 숫자를 훅에 넣기 / 남의 문구·마스코트를 그대로 쓰기(구조만 가져온다) |

영상 길이 35초. 대사 분량과 말 속도는 ow-reels 가이드 7절 표로 계산한다(우리 릴스 기본 5.5자/초와 다르니 섞지 않는다). 화면은 위 그래픽, 가운데 자막, 아래 진행자(우리는 싱크곰)로 나눈다.

| 구간 | 시간 | 역할 | 빈칸 틀 |
|---|---|---|---|
| 1 | 0~3초 | 결과 먼저(훅) | [결과]를 [시간]에 만들어요. / [결과 장면] |
| 2 | 3~8초 | 증거 한 개 | [확인한 숫자·출처]. |
| 3 | 한 문장 | 전환 | 방법 바로 알려드릴게요. |
| 4 | 8~30초 | 화면 따라 하기 3~4단계 | [단계 이름](동사로 끝). 단계마다 윗칸 그래픽이 바뀐다 |
| 5 | 한두 문장 | 결과 | 이제 [설명하면] 나머지는 [저절로]. |
| 6 | 한 문장 | 자료 예고 | [설치·설정 방법]을 문서로 정리했어요. |
| 7 | 마지막 5~7초 | 키워드 CTA | [브랜드 팔로우 한 줄]. 댓글에 [키워드]. 설치 문서는 DM으로 보내 드려요. |

## 6. 증거 카드뉴스 (카드 9장)

> 카드뉴스 키트에서 쓰는 공식이에요. 릴스 키트에서는 고르지 않아요.

| 칸 | 내용 |
|---|---|
| 이럴 때 | 공식 발표·숫자·원문 캡처가 있는 소식. 증거가 주인공일 때 |
| 표지 규칙 | 밝은 필름 사진 한 장, 한 색. 주인공은 싱크곰(사람 정면 얼굴은 쓰지 않는다). 제목 2줄, 줄당 4~13자, 마지막 줄은 블루 칩 위 흰 글씨. 속말(뱃지)은 한 줄, 공백 빼고 16자 안쪽, 읽는 사람이 속으로 할 말 |
| 첫 1초 | 해당 없음. 대신 1장 제목이 결과를 말하는 문장으로 끝난다("~알려 줘요", "~달라져요") |
| 끝 멘트 | 9장 한 장에 댓글 키워드 한 단어. 캡션은 funnel-cta.md 4절 |
| 우리 예 | 인생 프롬프트 편, 오퍼스 5.5 더 싼 이유 편, 뮤즈 해부 편(CARDNEWS.md 선례 폴더 이름). 문장은 원본 폴더에서 가져온다 |
| 하지 말 것 | 코드로 그린 차트·도형·목록 카드 / 캡처만 이어 붙이기(캡처와 사진을 번갈아) / 약속한 개수를 카드에 다 싣기(카드엔 5개, 나머지는 자료로) / 그림에 이미 있는 말을 본문에 다시 쓰기 |

| 장 | 역할 | 빈칸 틀 |
|---|---|---|
| 1 | 표지 | 속말 [읽는 사람이 속으로 할 말] / 제목 [첫 줄] / [결과 명사구 칩] |
| 2 | 인트로 + 사진 | 요즘 [도는 것]. 오늘 보여 드릴 것은 [무엇]. |
| 3~5 | 내용: 실제 캡처 + 빨간 표시, 또는 AI 답 대화 카드 | 제목 [결과로 끝나는 문장] / 본문 3줄 해요체 [줄1] [줄2] [줄3] |
| 6 | 쉬어 가기: 생성 사진 + 통찰 한 줄 | [원본과 다른 점 한 줄] |
| 7~8 | 내용: 캡처 | 3~5와 같은 꼴 |
| 9 | 댓글 장 | [상황]이라면, 댓글에 [키워드] 한 단어만 남겨 주세요. 받는 것 ✓ [자료] |

그림은 실물만 쓴다(원문·숫자는 캡처, AI 답은 대화 카드, 분위기는 생성 사진). 출처 줄을 카드에 단다.

## 7. 화면 카드뉴스 (카드)

> 카드뉴스 키트에서 쓰는 공식이에요. 릴스 키트에서는 고르지 않아요.

| 칸 | 내용 |
|---|---|
| 이럴 때 | 프롬프트 모음, 활용 결과물, "이렇게 넣었더니 이렇게 나왔다" 전후 비교. 앱 화면이 말하는 편 |
| 표지 규칙 | 어두운 사진 + 제목 2줄, 둘째 줄은 블루 칩(지난 표지 제목과 같은 말), 아래 ⓘ 한 줄 |
| 첫 1초 | 해당 없음. 결과가 먼저, 프롬프트는 뒤 |
| 끝 멘트 | 마지막 장 `get`: 편 사진 배경, "{상황}이라면," 아래 "댓글에 키워드 한 단어만". CTA는 이 장 하나이고 팔로우 장을 따로 두지 않는다 |
| 우리 예 | 인생 프롬프트 편을 옮긴 시안(`content/samples/screen-deck-life-prompts.json`). 문장은 그 파일에서 가져온다 |
| 하지 말 것 | 프롬프트부터 앞세우기 / 결과 장에 지어낸 답 쓰기(답은 실제로 받은 것에서 발췌) / 같은 화면 세 장 넘게 잇기 / 팔로우 장을 따로 만들기 |

| 장 | type | 역할 | 빈칸 틀 |
|---|---|---|---|
| 1 | cover | 표지 | 제목 [첫 줄] / [둘째 줄 칩] |
| 2 | window | 공감 창 메모 | [읽는 사람이 속으로 하는 말] |
| 3~5 | chat, compare | 결과 여러 장(밝은 화면) | 머리줄 [모드·모델] / 내 말풍선 [넣은 말] / AI 답 [실제 답 발췌] / 전후는 before [빼기 전] after [뺀 뒤] |
| 6~7 | prompt | 복사용 프롬프트(어두운 화면) | 01. [상자 제목] [프롬프트 본문, 바꿀 곳은 [빈칸]] |
| 8 | app | 팁(밝은 화면) | [설명 한 줄] / [손글씨 한 줄] |
| 9 | get | 마지막, 댓글 장 | {상황}이라면, 댓글에 [키워드] 한 단어만. 받는 것 ✓ [자료] |

밝은 화면과 어두운 화면을 섞는다. 순서·훅·사진·글·메타 규칙은 6번과 같다.

## 7개 공통 규칙

- 훅 후보는 hooks.md 1절의 서로 다른 유형으로 5개 이상 만들어 `scripts/score_hook.py`로 채점하고, 최고점만 사실 확인으로 거른다. 카드뉴스 표지 제목도 같은 방식으로 채점한다.
- 캡션은 funnel-cta.md 4절 꼴, 행동(CTA)은 한 편에 하나.
- 댓글 키워드는 마지막 화면(마지막 장) 글자와 같은 단어. 다르면 자동 답장이 안 걸린다.
- 지어낸 숫자·경험·다수 금지. 확인 못 한 숫자는 [확인 필요]로 비워 두고 묻는다.
- 말투, 금지어, 점검표 A·B·C, 분량은 SKILL.md 0절과 scripts.md 3~4절을 따른다.
