# 대본 · 훅 규칙

40~50초 릴스 대본은 **9~10줄**이다. 한 줄이 한 화면(프레임)이 된다.
첫 줄은 훅 화면, 마지막 줄은 마지막 화면(`episode.json` 의 `cta`: `save` 저장 · 팔로우 / `keyword` 댓글에 키워드), 그 사이가 본문이다.

---

## 0. 브랜드 톤 (`brand.json` 의 `tone`)

대본을 쓰기 전에 `tone` 을 읽는다. 아래 규칙(§2 문장 규칙 · §4 쉽게 설명하는 법)은 말투와 상관없이 지킨다. 말투는 **끝말과 문장 길이**만 바꾼다.

| `tone.speech` | 끝말 | 문장 | 같은 줄을 쓰면 |
|---|---|---|---|
| `friendly` 친근한 존댓말 (기본) | ~요 · ~거든요 · ~더라고요 섞기 | 15~25자 | "저도 회의 메모를 통째로 넣고 요약만 시켰거든요." |
| `expert` 차분한 전문가 | ~습니다 · ~입니다 · ~요 섞기, 감탄 없이 | 15~25자, 근거나 숫자를 앞에 | "회의 메모를 통째로 넣으면 요약이 더 길어집니다." |
| `punchy` 짧고 센 단정 | ~다 · 명사로 끊기, 질문 하나는 허용 | 8~15자, 한 줄에 두 문장도 된다 | "요약만 시켰다. 더 길어졌다." |

- `tone.about` 은 주제 후보를 낼 때 쓴다(0-2). 채널이 다루는 것과 먼 주제는 후보로 내지 않는다
- `tone.words_like` 의 말은 자연스러울 때만 쓴다. 억지로 끼우지 않는다. `tone.words_avoid` 의 말은 대본 · 화면 · 캡션 어디에도 쓰지 않는다
- 말투가 바뀌어도 훅 카드 세 줄의 꼴(§3)과 마지막 줄의 "저장" · 댓글 키워드는 그대로다
- 캡션 · 고정 댓글 · DM(`references/meta.md`)도 같은 말투로 쓴다

## 1. 뼈대: 개념 하나 + 할 일 셋

| # | 역할 | 예 (회의록 편) |
|---|---|---|
| 01 | **훅** | 클로드 회의록 정리가 느린 건, 회의가 길어서가 아니에요. |
| 02 | **1인칭 결핍**: 나도 그랬다 (사용자가 말한 불편이 있으면 그 말로, 없으면 보는 사람 공감형 "○○ 하다 보면 늘 ○○하죠") | 저도 회의 메모를 통째로 넣고 요약만 시켰거든요. |
| 03 | **원리 한 줄**: 어려운 말은 버린다고 대놓고 말한다 | 어려운 프롬프트는 몰라도 돼요. 뭘 뽑을지만 먼저 정하면 됩니다. |
| 04 | **개수 선언 + 이름 붙이기**: 두 글자 이름 | 정할 건 딱 세 개예요. 결정, 할 일, 질문. |
| 05~07 | **스텝, 같은 문형 반복**: 먼저 / 다음은 / 마지막은 | 먼저 결정. 회의에서 정해진 것만 한 줄씩 뽑아 달라고 해요. |
| 08 | **대비 또는 출처**: 전과 후, 숫자 둘의 낙차 | 그러면 긴 요약 대신, 다음 회의에 바로 쓸 세 칸이 남아요. |
| 09 | **마지막 화면**: `cta` 꼴대로 | (keyword) 세 칸 프롬프트는 자료에 담았어요. 댓글에 회의록. 도움 됐다면 팔로우해 주세요. · (save) 필요할 때 꺼내 보게 저장해 두세요. 도움 됐다면 팔로우해 주세요. |

- 스텝이 셋이면 **9줄**, 다섯이면 **10줄**(04 선언을 03에 붙이고 05~09 를 스텝으로)
- 마지막 줄 꼴은 `cta` 로 갈린다. 「자료 만들기」가 없으면 `save` 가 기본이다
  - `save`(저장 · 팔로우, 자료 없이): **"필요할 때 꺼내 보게 저장해 두세요. [마감 문구]."** 마지막 화면 카드에는 `recap` 세 줄(스텝 이름 + 한 줄 요점, 줄당 한글 12자 안쪽)이 뜬다. "댓글에"는 쓰지 않는다
  - `keyword`(댓글로 자료 주기): **"[자료 내용]은 자료에 담았어요. 댓글에 [키워드]. [마감 문구]."** `kit` 의 이름 · 구성 3줄 · 키워드를 같이 정한다. 자료(`kit.html`)는 렌더 뒤에 만든다
  - 마감 문구는 `brand.json` 의 `cta.tagline` 과 같은 말로 쓴다. 그래야 마지막 화면 글자가 말에 맞춰 뜬다
- **다음 편 예고를 넣지 않는다.** 마지막 3초는 한 가지(저장 또는 댓글)만 시킨다

### 1-1. 도구 · 스킬 N개 소개형

여러 개를 소개하는 편은 결핍 · 원리를 빼고 곧게 간다.

| # | 역할 |
|---|---|
| 01 | 훅 |
| 02 | **쓰는 이유** 한 줄: 직접 써 보고 맞는지 확인한 이유만 |
| 03~ | **N번 소개**: "N번, 이름. 하는 일." 같은 문형. 도구마다 **불편 한 줄 + 해결 · 증거 한 줄** |

### 1-2. 유튜브 쇼츠판

쇼츠에는 댓글 자동 DM 이 없다. **마지막 줄만 바꾼 판**을 따로 만든다(새 편 폴더로 복제 → 마지막 줄 → `voice --line`).

| 판 | 마지막 줄 |
|---|---|
| 인스타 릴스 | …는 자료에 담았어요. 댓글에 [키워드]. [마감 문구]. (save 꼴이면 쇼츠판을 따로 만들 필요 없다) |
| 유튜브 쇼츠 | …는 고정 댓글에 있어요. 도움 됐다면 구독과 좋아요 부탁드려요. |

쇼츠는 60초 안쪽이어야 한다. 고정 댓글에 자료 링크가 실제로 있어야 한다.

## 2. 문장 규칙

`python3 engine/reel.py lint <편>` 이 숫자로 잡는 것은 ✓ 표시.

1. ✓ **한 문장 25자 안쪽**(공백 빼고). 한 줄에 1~3문장. 한 줄에 한 가지만
2. **스텝은 같은 문형으로.** "먼저 ○○. …" / "다음은 ○○. …" / "마지막은 ○○. …"
3. ✓ **"첫째 · 둘째 · 셋째" 표지판 금지.** "먼저 · 다음은 · 마지막은"
4. **04번에서 이름을 붙인다.** 두 글자 이름이 있어야 스텝이 기억에 남는다
5. **어려운 말은 03번에서 버린다.** "○○니 ○○니 몰라도 됩니다"
6. ✓ **끝말을 섞는다.** 예요 / 거든요 / 합니다 / 돼요. 같은 끝말이 세 줄 연속이면 하나를 바꾼다
7. **영어는 영어로 적는다**(`CLAUDE.md`, `/context`). 설명 없이 못 알아듣는 약어는 넣지 않는다
8. **숫자는 대비로.** "30번 → 1번". 숫자 하나보다 둘의 낙차가 남는다
9. ✓ **줄표(—) 금지.** ✓ **금지어**: 게임체인저 · 혁명적 · 무조건 · 떡상 · 대박 · 미쳤다
10. **요즘 한국에서 실제로 쓰는 말로.** 번역투 · 내가 지어낸 조합어 · 커뮤니티 은어를 쓰지 않는다. **소리 내어 읽어 보고 입에서 걸리면 고친다**
11. ✓ **어림 길이 40~50초.** 공백 뺀 글자 220~275자 안쪽(한국어 TTS 는 초당 5.5자 안팎). **무료 목소리(edge)는 더 느려서** 9줄에 238자가 실제 57초, 270자가 62초 나왔다. 무료 목소리면 9줄 기준 190자 안팎으로 쓰고, 음성을 뽑은 뒤 로그의 「합계」(실제 길이)로 다시 확인한다. `lint` 도 음성을 이미 뽑았으면 실제 길이로 센다

### 읽는 글과 보이는 글을 나눌 때

TTS 가 숫자나 영어를 이상하게 읽으면 줄에 `say` 를 준다. 목소리는 `say`, 자막은 `text` 를 쓴다.

```json
{ "scene": "대비", "text": "28개 중에 3개만 남겨요.", "say": "스물여덟개 중에 세개만 남겨요." }
```

**두 문장의 띄어쓰기 덩어리 수가 같아야 한다.** 위는 둘 다 4덩어리다. `say` 를 "스물여덟 개"처럼 띄우면 덩어리가 늘어 어긋나고, 그러면 자막이 읽는 글로 나간다.

## 3. 훅

### 3-1. 대본 첫 줄: 쓰는 꼴

| 유형 | 꼴 | 쓸 때 |
|---|---|---|
| **A 오귀인** | "[문제]는 [통념] 때문이 아니에요" | 보는 사람이 이미 그 문제를 겪고 있을 때 |
| **B 숫자 + 전수** | "[N개]를 전부 [해 봤습니다]" | **실제로 다 해 봤을 때만.** 안 했으면 못 쓴다 |

**후보 3개는 서로 다른 꼴로** 낸다: A 오귀인 · B 숫자+전수(실제로 다 해 봤을 때만) · C 조건+결과(아래) · D 나만 놓친 격차(아래). B 를 못 쓰면 A · C · D 로 3개.

- **첫 문장이 곧 훅이다.** "안녕하세요 · 여러분 · 오늘은"으로 시작하지 않는다(✓ lint)
- 보는 사람 **1인칭**으로 쓴다("내가 쓴 글", "내 계정"). "너 · 네" 반말은 쓰지 않는다
- **조건 + 결과가 세다.** "지금 꺼야 하는 설정"보다 "지금 안 끄면 남이 보는 설정". 단 결과는 사실이어야 하고, 본문 안에 범위를 좁히는 문장을 하나 넣는다
- **"나만 놓치고 있다"가 "손해 본다"보다 먼저다.** 없는 다수를 지어내지 말고("남들은 다 껐어요" ✗) 내 얘기로 격차를 만든다("저는 확인해 본 적이 없었어요")

### 3-2. 훅 카드: 배지 한 줄 + 타이틀 3줄

영상 맨 앞 1.4초, 말 없이 뜨는 카드다. **릴스 커버(`out/cover.png`)도 이 카드다.**

```
배지    상황 · 지목        "회의 끝나고"  "코딩 못해도"  "○○ 쓰는 사람만"
1줄     대상 (도구 이름)   "클로드 회의록"
2줄     강한 말            "가장 빠른"  "꼭 깔아야 하는"  "남들은 이미"
3줄     명사구 · 칩        "정리법"  "설정 3개"  "나만 몰랐다"
```

- **줄당 한글 5~6자.** 한 줄이 길면 세 줄이 다 같이 작아진다(엔진이 가장 긴 줄에 맞춰 크기를 정한다)
- **3줄을 지킨다.** 4줄로 늘리면 약해진다. 셋째 줄은 **명사구로 끝낸다**("~해야함" 같은 문장형 마감은 약하다)
- **숫자는 2줄에, 우리가 주는 것에 붙인다.** "주식 10개"는 종목 추천으로 읽힌다 → "프롬프트 10개"
- **배지 꼴을 3편 연속 같게 쓰지 않는다.** 피드에서 같은 영상으로 보인다
- **카드 문구와 첫 줄 말은 같은 말로 잇는다.** 커버에서 읽은 말을 첫 1초에 그대로 듣게 한다. 첫 줄 둘째 문장에서 한 겹 더 말한다
- 금지어 대신 쓸 말: "무조건 설치" → "꼭 깔아야 하는 · 안 깔면 손해인 · 깔고 시작하는"

### 3-3. 후보를 내는 법

- **최소 3개, 서로 다른 꼴(§3-1 의 A · B · C · D).** 같은 꼴 3개는 후보가 아니라 문장 다듬기다
- 후보마다: 유형 · 배지 · 타이틀 3줄 · 첫 줄 말
- **추천 1개를 표시하고 이유를 한 줄로**
- 숫자를 맞추려고 숫자를 지어내지 않는다. 근거(1단계)에서 확인 못 한 후보는 버린다

## 4. 쉽게 설명하는 법

1. **비유는 편 전체에 하나.** 03에서 세우고 04~08이 이어받는다(회의록 편: "세 칸")
2. **용어는 첫 등장에 괄호로 풀거나 아예 쓰지 않는다.** 컨텍스트(클로드가 기억하는 범위)
3. 한 화면에 세 문장 이하
4. 일하는 사람 말투. "진짜진짜 · 완전 · ~해용 · !!!" 같은 과한 말은 쓰지 않는다

## 5. 점검표 두 개 (Claude 가 스스로 채점한다)

대본을 쓴 뒤 **사용자에게 묻지 않고** 스스로 채점해서 `episode.json` 의 `scores` 에 넣는다(항목당 5점). 사용자는 씬 대시보드에서 점수와 함께 본다.
**20점 아래인 쪽이 있으면** 5점 미만 항목을 고쳐 다시 쓴 뒤 넘어간다.

**A. 대본 품질 (25)**
1. 직관성: 처음 들어도 비유가 바로 이해되는가
2. 후킹력: 첫 문장이 3초 안에 손가락을 멈추게 하는가
3. 자연스러움: 사람 말투인가(끝말이 섞였나, 대구 · 표지판이 없나)
4. 리듬: 문장 길이가 들쭉날쭉한가, 읽을 때 처지는 데가 없나
5. 구체성: 실제 도구 이름 · 실측 숫자 · 복사해 쓸 것이 있는가

**B. 퍼지는 구조 (25)**
1. 훅 꼴(§3) 충족
2. 증거: 실측 숫자나 실제 결과가 클라이맥스에 있는가
3. 붙잡기: 개수 선언 · 진행 표시 · 다음 정보에 대한 궁금증
4. 마지막 행동: (keyword) 키워드 + 자료 가치(영상보다 정보가 많다) + 받는 법이 쉽다 · (save) 다시 꺼내 볼 이유가 분명하고 `recap` 세 줄이 본문 스텝과 같은 말이다
5. 마감: 마감 문구로 닫았나, 다음 편 예고가 없나

대시보드에서 사용자가 고치라고 한 줄만 다시 뽑는다. 줄의 역할(뼈대)이 바뀌면 그 뒤 줄도 맞춰 고친다.
